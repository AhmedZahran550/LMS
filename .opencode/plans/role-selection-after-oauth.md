# Role Selection After OAuth

## Goal
Replace the upfront role-selection modal (in `SocialLoginWithPopup`) with a post-auth `/choose-role` page. New users pick their role AFTER successful OAuth. Existing users skip this step entirely.

## Why
- Fewer clicks before auth (no modal blocking the popup open)
- Role selection happens after identity is confirmed (better UX)
- Cleaner separation: auth ≠ role assignment

## Design

### Flow

```
1. Click "Continue with Google"
2. Popup opens immediately → OAuth flow → Google consent
3. Backend callback:
   a) Existing user → HTML with {needsRole:false, user, accessToken, refreshToken}
   b) New user → HTML with {needsRole:true, tempToken, user:{email,firstName,lastName}}
4. Popup HTML postMessages to opener → window.close() → about:blank
5. Opener receives message:
   a) needsRole=false → setAuth() → redirectByRole() → popupRef.close()
   b) needsRole=true → store tempToken → router.push('/choose-role') → popupRef.close()
6. /choose-role page:
   - Reads tempToken from zustand persist
   - Shows Learner / Instructor cards
   - On selection: POST /auth/complete-registration { tempToken, role }
   - On success: setAuth(user, accessToken, refreshToken) → redirectByRole()
```

### Backend: New temp token

Generated by `auth.service.ts`:

```ts
private generateTempToken(profile: SocialProfile, provider: AuthProvider): string {
  return this.jwtService.sign(
    {
      temp: true,
      email: profile.email,
      firstName: profile.firstName,
      lastName: profile.lastName,
      provider,
      providerId: profile.id,
      picture: profile.picture,
    },
    { expiresIn: '5m' },
  );
}
```

No user is created in the DB until `/complete-registration` is called.

### Backend: `validateOrCreateUser` changes

Current: creates user in DB for new users (with role).
New: returns `{tempToken, user: partial, needsRole: true}` for new users.

Existing users (found by providerId or email) → unchanged (full JWT + `needsRole: false`).

### Backend: `POST /auth/complete-registration`

Validates tempToken, creates user with chosen role, returns full JWT + user profile.

## Backend `buildSuccessHtml` Payload Shapes

```ts
// Existing user → no changes to current flow
{ type: 'OAUTH_SUCCESS', needsRole: false, user, accessToken, refreshToken }

// New user → temp only, no real tokens yet
{ type: 'OAUTH_SUCCESS', needsRole: true, tempToken, user: { email, firstName, lastName } }
```

`buildSuccessHtml` becomes generic:

```ts
private buildSuccessHtml(payload: Record<string, unknown>, origin: string): string {
  const data = JSON.stringify({ type: 'OAUTH_SUCCESS', ...payload });
  ...
}
```

## Frontend `handleOAuthMessage` Type

```ts
type OAuthSuccessPayload = {
  type: 'OAUTH_SUCCESS';
  needsRole: false;
  user: UserProfile;
  accessToken: string;
  refreshToken: string;
} | {
  type: 'OAUTH_SUCCESS';
  needsRole: true;
  tempToken: string;
  user: { email: string; firstName: string; lastName: string };
};
```

## Edge Cases

| Case | Behavior |
|------|----------|
| Existing user (by providerId or email) | Full JWT, `needsRole: false` → normal login |
| New user completes `/choose-role` | User created, real JWT returned |
| New user gets temp token but closes /choose-role | No user created; next OAuth = still new → new temp token |
| Temp token expired | `/complete-registration` returns 401 → redirect to login |
| Temp token tampered | JWT verification fails → 401 |
| Same email used later with different provider | Found by email → existing user (full JWT, links new provider) |
